## Architectural result

Consultation and Dawa now share one deterministic medication review engine and one UI vocabulary. The engine evaluates only its documented finite scope, emits `HOLD`, `REVIEW_REQUIRED`, `NO_FLAGS_IN_SUPPORTED_CHECKS`, or `NO_MEDICINES_PROPOSED`, and records the rule version plus an input fingerprint. Package strength is never interpreted as an administered dose. Human edits or patient-context changes invalidate the previous review. Review notes retain findings rather than removing them.

Emergency output now comes from one builder. Because this repository has no clinically approved scenario-specific emergency treatment set, every current RED category produces a truthful unsupported-protocol state and urgent referral instructions without a medication order. The same stored payload supplies the graph gate and UI referral packet.

## Phase 3 architecture and storage result

Phase 3 adds a versioned, deterministic consultation-intake layer on top of the Phase 2 canonical snapshot.

- **Transcript provenance.** Every complaint (voice or typed) becomes a `TranscriptProvenance` carrying encounter id, source, source media artifact, raw text, corrected text, accepted text, declared/detected language, provider, confidence, normalization, confirming actor, confirmation time and version. RAW → CORRECTED → ACCEPTED are distinct; the original is never overwritten. Real-mode ASR failure produces `UNAVAILABLE` with a degraded reason and no canned content.
- **Normalization.** `normalize_text` keeps the immutable original and derives a normalized form (NFKC/casefold/whitespace) with a method + status; failure preserves the original and returns `FAILED` without fabrication. Provider ASR script conversion (`script_utils.py`) remains upstream work and is untouched.
- **Structured observations.** `ClinicalObservation` rows preserve question id, concept, value, unit, normalized value/unit, assertion (PRESENT/ABSENT/UNKNOWN/UNASSESSED), source, entering actor, observation time, verification state, snapshot version and definition version. `UNKNOWN` is never equated with `ABSENT`; `UNASSESSED` is never equated with `NORMAL`.
- **Versioned adaptive questions.** One respiratory/TB history pathway (`respiratory_tb_history`, version `2026-09-07.1`) defines 25 deterministic questions with ids, concepts, labels, input types, allowed units, required/important flags, dependency conditions and a version. Dependent questions appear only when their prerequisite is PRESENT; inactive answers are retired. The LLM never invents questions.
- **Early deterministic triage.** A new `early_safety` graph node runs deterministic rules immediately after accepted history. RED routes straight to the emergency protocol before structure/vision/reasoning (proven by event ordering: `VOICE_TRANSCRIPT_CONFIRMED` → `EARLY_SAFETY_SCREEN` → `EMERGENCY_PROTOCOL`, with no `STRUCTURE_EXTRACTED`). Later malformed provider output cannot clear deterministic RED. `INSUFFICIENT_DATA`, `NO_CONFIGURED_FLAG`, and `UNSUPPORTED_SCOPE` are distinct truthful states; `NO_CONFIGURED_FLAG` explicitly does not claim the patient is safe.
- **Snapshot persistence.** On graph completion the access layer appends an optimistic-locked, versioned `ClinicalContextSnapshot` containing the accepted history, structured observations, pathway selection and triage assessment. Provenance (actor, source, unit, timestamps) survives restore, and a concurrent context change raises rather than silently overwriting older evidence.
- **Guided regional Consultation journey.** The primary Streamlit Consultation entry is wired as a step-oriented flow: **Step 1 Complaint** (typed complaint or secure audio upload + declared language) → **Step 2 History** (RAW / editable CORRECTED / explicit ACCEPT confirmation; a correction that removes configured urgent evidence is blocked unless reviewed with a reason) → **early deterministic emergency screen** → **Step 3 Assessment** (the worker may confirm the respiratory/TB pathway candidate — worker confirmation is required, and without confirmation the pathway remains pending — then answers only the relevant adaptive questions + vitals + allergies/current medicines) → **Step 4 Current assessment** (truthful RED/YELLOW/NO_CONFIGURED_FLAG/INSUFFICIENT_DATA/UNSUPPORTED_SCOPE card with triggering evidence + "Information still needed") → **Review** (HITL medication/review) → **Next Step** (referral/emergency packet or doctor-report handoff). Encounter identity (patient, age, facility, worker, encounter ID/status) is always visible; JSON/audit detail stays in expandable sections. The legacy non-guided "Start consultation workflow" button keeps the pre-existing transcript→structure protocol intact for prior tests.

## Clinical status

Software evidence proves deterministic behavior for the recorded synthetic examples. It does not prove clinical accuracy, sensitivity, patient benefit, prescribing authority, comprehensive interaction coverage or safety in real patients. The evidence register and exact supported scope are in `docs/MEDICATION_EVIDENCE.md`; independent clinical review remains pending for all three phases.

Phase 3 triage/intake behavior is engineering-verified on the documented synthetic fixtures (positive/negated/negated-positive per configured rule, structured age/duration triggers, insufficient-data and unsupported-scope states). It is not a clinical validation study. A01 (emergency treatment content) remains `BLOCKED — CLINICAL REVIEW REQUIRED`; every current RED category still produces a truthful unsupported-protocol referral without a medicine order.
