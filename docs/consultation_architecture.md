# Consultation implementation

The existing Streamlit shell opens the consultation workspace. Dawa Check and District View retain their existing implementations and data. New consultation encounters use `consultation.db`; the legacy diagnosis/prescription graph is not called by the new consultation screens.

## Confirmed evidence and persistence

`store.py` is the transaction boundary for cases, append-only facts/events, drafts, derived outputs and persistent jobs. Facts retain typed values, units, sources, confidence, source quotes and supersede IDs. Proposals cannot change urgency or supersede confirmed evidence. Corrections invalidate dependent outputs; the UI displays fact/urgency changes and medicine-check versions. Packet review is rejected if its input facts or media change concurrently. Medicine reconciliation and considerations have explicit dependency keys; SBAR depends on the whole encounter.

Initial pregnancy is a confirmed ledger fact and appears in the SBAR background and bilingual read-back; the compact header and doctor view also show pregnancy and language. Reviewing an older case can append its exact pregnancy answer from the existing intake/correction event, with the source event recorded, without rewriting old audit rows. It never infers a missing answer.

Review reads case/facts/events/derived inputs together, then checks fact IDs, media IDs, care-event revision and intake/consent revision again before saving. A consent withdrawal/regrant is detected even if the final demographic values match. Sending checks these revisions as well as read-back and medicine acknowledgement. Packets from the earlier input contract are displayed as stale until regenerated. Local worker questions invalidate packets even while sharing is inactive; background recomposition cannot silently restore a withdrawn handoff.

Typed age, validated vitals and typed point-of-care tests are separate contracts. Clinical thresholds and age bands are editable configuration marked pending review. Missing critical information keeps urgency at least AMBER. AI concern can raise urgency only with current confirmed citations; its source dependencies expire when corrected. Every RED interrupt and fired rule is audited.

DOB-derived ages retain `date_of_birth` and `as_of` in the immutable age fact. `Age.from_record()` validates that those dates agree with the recorded age. Reopening an encounter preserves its original age reference instead of recalculating a new pathway silently; explicit age corrections remain audited. A conflicting typed age/DOB requires confirmation before intake can be created. DOB is included in bilingual read-back and exported as FHIR Patient.birthDate only when actually recorded. Older typed-age records do not acquire an inferred DOB.

`timeutils.py` uses the IANA timezone configured in `consultation.yaml` (Asia/Karachi) for calendar dates and readable follow-up times. DOB and laboratory future-date validation use that local date; UTC remains the storage/scheduler basis. A missing timezone database or invalid zone raises a configuration error instead of silently using the host's date. The existing requirements already include tzdata.

## Checkpointed review workflow

`pipeline.py` implements an actual LangGraph review graph: intake, danger screen, conditional emergency lane, confirmed-fact snapshot, question planning, measurement validation, medicine resolution/safety, evidence retrieval, constrained considerations, verification, packet composition, worker confirmation interrupt, routing, doctor response interrupt, patient card and follow-up data. Background packet recomposition uses an ephemeral graph so it cannot overwrite an active human interrupt. Provisional doctor replies loop back to the doctor gate. Worker communication requests can reopen the doctor gate through a persistent review job. The service layer owns atomic writes; graph replay does not append duplicate clinical facts or send messages. SQLite checkpoints are in `<case database>.workflow.db`. The graph coordinates the review/handoff boundaries; the collection UI and persistent scheduler also use the Store directly. It is not a claim that every widget interaction is an independent LLM agent or pathway subgraph.

## AI and human decisions

`ai.py` uses the existing provider router. The worker explicitly enables live extraction, vision or question rewording. Text/vision proposals require worker confirmation. The model receives serialized patient data and approved keys/choices. The considerations model selects eligible catalogue IDs and current fact IDs; code renders the supporting/negative evidence, gaps, tests and references. Ranking expresses evidence coverage/catalogue order, not disease probability. General collect-and-send cases do not receive respiratory diagnostic reasoning.

Live calls have a foreground wait limit of 25 seconds, configurable up to 60 with `CONSULTATION_AI_TIMEOUT_SECONDS`. At most two provider jobs run concurrently; identical in-flight inputs are reused. A timed-out SDK request may continue until its SDK returns, but it cannot confirm evidence or modify an encounter. Late structured text responses can fill their input-specific encrypted cache. Cached/manual fallback is explicit. Recorded audio stays available if transcription fails. One live synthetic extraction succeeded through the configured Gemini provider; that is connectivity/schema evidence, not a validation of speech, language or medical accuracy.

`scripts/warm_consultation_cache.py` uses the same `ai.json_cache_path()` and encrypted atomic writer as live text responses. The key binds operation, schema, question catalogue and exact input, including the age pathway when present. Default fixtures are authored synthetic examples; no providers are called and no patient case is changed. Existing valid responses are preserved; legacy plaintext is encrypted. `--manifest <path>` accepts `{ "synthetic": true, "entries": [{ "task": "extract", "input": { ... }, "output": { ... } }] }` for exact-input fixtures of supported operations; the complete set is validated before writing. `--overwrite` explicitly replaces valid existing responses. This does not prewarm arbitrary future requests or establish model accuracy.

`languages.py` separates spoken language from automatic transcription. English/Urdu retain bounded provider routing; opt-in Sindhi/Punjabi/Pashto drafts use explicit-language Groq Whisper, and opt-in Saraiki/Balochi attempts use explicit multimodal Gemini prompts. All regional drafts require named bilingual review and retain manual fallback; language accuracy is unvalidated. `voice.py` owns atomic recording retention, late-result guards, exact transcript/recording review and source-bound proposals with previous-answer versions. Draft/source/answer changes prevent stale confirmation. Transcript correction reopens previously confirmed source-bound facts for recheck. `speech_evaluation.py` scores independently supplied references by language/dialect/device/provider/noise, separates synthetic data and stores encrypted immutable reported results without declaring a language validated. See `voice_story_completion.md`. `illustrations.py` renders schematic collection aids; `questions.collection_status()` distinguishes known/unknown/not-asked documentation.

`speech_audio.py` binds audio to exact text/language. Fixed recordings and optional Gemini WAVs are encrypted; generation requires explicit action. Human recordings take precedence; browser speech requires a matching voice. The fixed bundle contains 66 English and 38 Urdu prompts, including all danger wording; 27 wider Urdu prompts remain unprepared. The builder reuses caches, prioritizes danger wording and supports an explicit matching-language offline eSpeak fallback. Generated audio remains unreviewed. Read-back and complete doctor-guidance recordings have separate exact-source/listening confirmation guards.

`content_review.py` exports exact configuration/question/consideration/medicine/observation snapshots and hashes. Optional fixed audio and schematic danger diagrams are packaged without patient encounters. Real review reports bind a current scope/hash, relevant role and date. Reports are encrypted, append-only and labelled reported-only/unverified identity; they do not activate dosing/regional entries or establish independent clinical validation.

## Handoff identity, routing and timing

`routing.py` owns transactional handoffs and compatible reviewer assignment. A send, validated returned task or actively shared worker communication request creates `HANDOFF_STARTED` with a unique ID, UTC send time and current simulated-clock offset. Doctor acknowledgements/replies and queued escalation bind that cycle. The doctor UI retains its reviewed handoff ID, and a stale response cannot acknowledge a newer cycle. Consent withdrawal cancels sharing without creating another handoff. Legacy sent cases can still use their recorded send timestamp until an explicit new handoff.

Configured synthetic reviewers have persisted available/busy/offline states and notes, with encrypted append-only roster audit. Matching preserves age/pregnancy group and language; an existing eligible reviewer is preferred, availability changes reassign unacknowledged cases, and the first escalation attempts a compatible alternate. Missing matches stay explicit. `pipeline.py` provides a routing preview; the Store selects from current availability at handoff time. All identities and external delivery remain simulated. Urgency-specific delay lists are validated as three increasing minute offsets; prototype defaults remain 10/20/30 for every level until partner review.

`metrics.py` projects acknowledgement/reply delays per handoff from actual event timestamps. A new unanswered handoff returns pending values instead of subtracting an old reply from the latest send time. History, task totals and simulated-clock minutes remain visible, with withdrawal boundaries preserved. These application timings do not measure physician work time, clinical correctness or patient outcomes.

## Doctor-selected prescription product

`dosing.py` validates the recorded formulation, printed strength and route. The doctor enters their amount in mg per dose; code does not infer a dose, convert a printed volume/tablet count or supply clinical ranges. A comparison requires an explicitly reviewed table and exactly one matching single-ingredient/formulation/strength/route/age entry with reviewer/date/source metadata. Incomplete/ambiguous entries fail closed. Confirmed valid weight and finite positive mg are required. The clinical table remains empty/pending, so no live amount is automatically accepted by this helper.

Product and regimen details survive drafts, replies and confirmed doctor-plan facts. The doctor enters daily count/maximum if needed, course length and indication explicitly. Reviewed entries may constrain absolute per-dose amount, absolute/weight-based daily maxima, frequency and duration, and require a matching indication. The stricter supplied daily cap is checked using only the doctor's entered mg and daily count. Missing reviewed limits/inputs remain visible, and as-needed selection cannot bypass the maximum count. Per-dose and whole-configured-regimen results remain separate.

Prescription acknowledgement binds product, regimen, amount, schedule, free text and reviewed case; edits reset it. Checking fields never become inferred patient instructions. Combination/multiple-medicine dosing, organ function and free-text schedule semantics still require independent doctor review, and no other medicine flag is suppressed. See `dose_entry_contract.md` for the exact reviewed-entry contract and limits.

`reported_doses.py` separately binds a human-confirmed intake amount/regimen to the exact current medicine-history row hash. No mg amount is inferred from images, volume or tablet count. Unknown amount/frequency/duration requires a reason. `Store.reported_medicine_amount()` checks current row identity transactionally; medicine corrections retain only amounts still matching current rows. Reconciliation checks each reported amount against the same reviewed-entry contract, includes results in medicine-check versions and cites the amount facts in the packet. The shipped empty clinical table keeps these checks unavailable; no recommendation is generated.

## District and seasonal fever context

`epidemiology.py` validates a worker-confirmed illness country/province/district, reference date, unknown reason and reported exposure notes. Drafts remain unconfirmed until explicitly saved. `Store.confirm_fever_context()` guards concurrent edits and identical re-saves; corrections supersede the earlier fact and invalidate dependent packets/analysis. These facts appear in bilingual read-back, SBAR and exports; updated remote packets still require the normal review/read-back/send flow.

The empty/pending `config/fever_context.json` defines the future reviewed source contract. Matching requires an exact country/region/district, calendar month and inclusive validity date window. Malaria/dengue/typhoid context is displayed only with valid reviewed source metadata; absent, malformed, expired, mismatched or ambiguous entries remain unavailable. No model-generated prior, disease probability, diagnosis or urgency decision is derived from this module. Reviewed statements are separately labelled source context rather than claims proved by the exact ledger verifier.

Packets and doctor/wording review snapshots bind the catalogue content hash. Changed source content invalidates packets, rejects concurrent publication and requires current doctor review. The doctor sees current confirmed location/source context even while an older SBAR is superseded. See `fever_context_contract.md`; no real regional entries or approvals have been added.

## Packet, read-back and doctor loop

`packet.py` creates separate Situation, Background, Assessment and Request sections, a complete fact/media/audit appendix, full English/Urdu read-backs and a compact transport summary. Long cases are flagged when they exceed the text budget; clinical text is not silently truncated. `verify.py` accepts exact deterministic bilingual or canonical ledger sentences and blocks changed values, negations, units and citations. Arbitrary model prose is not semantically verified by an entailment model. Clinical hypotheses and rule interpretations remain separately labelled for doctor review. Open worker questions/barriers are copied from immutable communication events into the Request section with event citations; they are not presented as model-verified clinical facts or passed to the clinical reasoner as instructions.

`analysis_verifier.py` also checks constrained consideration IDs/eligibility, exact catalogue wording, current supporting/negative fact citations, configured gaps, source IDs and prohibited diagnosis/dose/probability fields. It does not establish clinical truth or unrestricted prose entailment. Packets bind the `ledger-and-considerations-v1` verification contract; older packets are stale until regenerated.

`readback.py` records named interpreter-confirmed regional-language wording against the complete English source, packet version and source hash. Written numbers and Latin medicine names are guarded conservatively, while full meaning/negation/units require human confirmation. Patient confirmation binds the exact chosen language/text; an edited translation requires reconfirmation before sending. Recorded/uploaded or generated-preview audio can be attached only after explicit listening confirmation and binds case, packet, language and text hash. This audio is not a new clinical observation, so attaching it does not invalidate its own packet. Retention includes its case-media reference. The offline read-back HTML embeds only matching confirmed audio and escaped complete text.

Sending requires consent, a current verified packet, matching patient/worker read-back, resolved proposals, the danger screen and acknowledgement of the current medicine-check version. A patient rejection blocks that packet version. The doctor can acknowledge, request typed history/vitals/tests/media tasks, author advice/diagnosis, select tests/referral/call, and enter a medicine schedule. Returned tasks are validated once, appended and recomposed for the doctor. Doctor-selected local/lab tests create persistent orders and worker tasks. Local results use typed point-of-care models; lab reports retain the issued text and optional case-scoped PDF/photo. Order/result events preserve pending, returned, unavailable and cancelled states. Re-saving a plan reuses prior requests; repeats require explicit selection. Returned results remain marked for doctor review, and recovery cannot close an outstanding order. Doctor draft replies hold their reviewed fact snapshot and require reviewing subsequent worker changes before saving. Schedule medicines are checked together with the reported medicines; no patient dose is generated. Reviewed dosing entries remain unavailable pending physician/pharmacist input.

Withdrawal of sharing consent removes the active remote handoff, cancels pending escalation jobs and blocks doctor tasks/replies. Regranting consent requires an explicit new review/read-back/send. Previously recorded facts/advice remain in the local audit.

## Guided measurement tasks

Doctor-requested vital measurements use `measurements.task_measurement()`, accepting both legacy scalar entries and typed values/units/methods. Temperature entries retain the original C/F value in the completion audit while the ledger uses normalised C. Respiratory tasks include their own case/task-scoped 60-second counter; a completed count populates only the draft, requiring the normal return action. Partial durations, fractional timer counts and timed claims for other measurements are rejected. Completed measurement records retain method/duration; unavailable readings retain a reason and unknown value. These are collection records, not independent validation of how the worker measured.

## Doctor-confirmed patient wording

Patient-language wording drafts retain assistance/source-hash metadata in the encrypted doctor draft. Every nonblank local-language plan requires explicit doctor approval bound to its exact text, source advice and reviewed fact/media/care snapshot; the server verifies that binding and records provenance. Edits invalidate the UI approval, and a new browser session requires confirmation again. Written number/unit pairs are preserved conservatively during AI rewording, in addition to medicine names and negation counts. These are text guards, not a general translation-equivalence proof; full meaning still requires doctor verification. Doctor-recorded audio has its separate complete-plan approval.

## Follow-up, drafts and media

A single background scheduler per database checks persistent jobs every ten seconds. Due jobs survive restarts; claims/generations prevent duplicate completions. Escalations and delivery remain simulated. Follow-up reminders appear in the worker inbox after a final plan; provisional replies await requested information/results. Ongoing symptoms schedule another check; worsening or new danger re-escalates. The service rejects contradictory recovered outcomes and retains unknown answers rather than recording fabricated negatives.

`worker_worklist()` reads a consistent saved snapshot across active cases. The worker view refreshes this action list every 15 seconds, prioritising RED, due follow-ups and pending doctor tasks, and showing counselling/referral/contact/questions. It recognises due scheduled jobs even before the scheduler emits a reminder. Closed cases leave the active list. Task cancellations/completions and follow-up submissions update the projection without maintaining a second queue.

`safety_update()` is separate from routine recovery follow-up. Worker-confirmed worsening, a new danger sign or inability to drink can be recorded before a final response, during pending tests or after case closure. Facts, urgency and an explicit reassessment request are written atomically. With active sharing the doctor queue and persistent graph gate reopen; otherwise the case stays in local review/emergency and no sharing is restored. Selecting recovery in an unfinished follow-up draft cannot block this separate urgent action. These observations never clear existing danger facts automatically.

Question answers, story text, measurement fields, structured medicine/allergy edits, doctor reply fields, all task answer types and follow-up answers save when committed/blurred. Task draft attachments retain encrypted case-scoped references across navigation; the worker can exclude an attachment from the returned answer. Explicit negative and zero values survive. Follow-up drafts bind the current doctor reply and follow-up cycle, so a new response or submitted check-in starts fresh. Confirmation remains explicit. This is not per-keystroke saving, and text left in an uncommitted browser editor cell cannot be guaranteed after a crash. Case URLs restore the saved encounter step. The Streamlit resource cache is keyed by database path and loaded Store-class identity so an updated service is not replaced by a cached older implementation; the scheduler reloads its Store reference on each iteration.

JSON payloads, draft content, model caches, graph checkpoints and newly uploaded media are encrypted locally. Case IDs, timestamps, stages and event types remain database metadata. Keys live in ignored `.consultation-keys` folders beside the case database and under `data` for media/cache. Back up the database, workflow database, media and their matching keys together; losing the keys makes encrypted content unreadable. Keys are scoped to the configured database path. Exports intentionally contain readable encounter data. There is no production authentication/TLS claim.

`Store.cleanup_media(retention_days=30, dry_run=True)` previews expired case media. Explicit `dry_run=False` applies the selected policy and records tombstones; the application does not invent or enable an institution's retention policy. Missing files display an unavailable-media message while the audit reference remains.

## Counselling and reported care handoffs

`care.py` is a Store mixin projecting reported counselling, referral/contact progress and worker questions from the same encrypted immutable events. Guidance receipts bind the exact doctor response; a newer response or changed clinical facts/media invalidates a successful confirmation of old guidance. Unknown understanding and requests for clarification require a reason. These are recorded human reports, not measured comprehension or proof of delivery.

Transport/arrival/admission reports, unavailable contacts and explicit doctor cancellation/reopening have stable IDs, correction history and case scope. Re-saving the same facility/call request reuses its handoff. Legacy events acquire deterministic projection IDs without rewriting their audit rows. New questions/barriers reopen the local doctor queue, renew simulated escalation only with active sharing consent, and queue a review that resumes the doctor graph gate. Worker requests must be explicitly marked answered in the doctor's new response. Clinical urgency does not decrease because a transport/contact status changes.

The doctor review snapshot includes a care-event revision alongside fact and media IDs, preventing a response from resolving outdated questions. Recovery checks generic tasks, open clarification requests, calls and active referral handoffs in addition to tests and current clinical evidence. Reporting referral while transfer remains pending retains follow-up; unresolved RED remains in the emergency lane. A requested photo/audio can return an explicit unavailable reason instead of requiring a fabricated attachment. Task cancellations keep linked orders consistent.

Counselling scripts, feeding/ORS, return precautions, local wording and medicine schedules are retained in the confirmed doctor-plan fact. Current reported care status is included in encounter JSON, the FHIR document narrative and downloadable patient cards. Notifications, clinician identity and external delivery remain simulated as scoped.

## Offline and interoperability boundaries

`transport.py` creates a lossless ZIP with per-file byte/hash manifests and optional original case-scoped media. Unavailable media is explicit; local paths are removed. A 50 MB bound applies without truncation. Packages split into 64 KiB JSON parts; the receiver rejects corrupt/mixed/unsafe data and reports missing indices before reconstructing. Received content is never automatically trusted as clinical evidence. Checksums provide byte integrity, not sender authentication. UI package downloads disappear after source/consent changes; transfer statistics are audited without storing the ZIP as another permanent case file.

`delivery.py` prepares encrypted append-only outbox requests for an optional partner-operated HTTPS gateway. Each request binds current consent/context, fact/media/care revisions, handoff and applicable packet/reply/source versions. Network I/O starts only after explicit confirmation with server-configured credentials; no scheduler automatically dispatches. Stable idempotency keys support safe partner deduplication and explicit retry. Ambiguous outcomes remain unknown, and gateway acceptance never becomes doctor acknowledgement or verified receipt. The current installation has no delivery credentials; local delivery remains simulated. See `consultation_integrations.md` for request/receipt schemas and in-flight consent limitations.

The quick danger component performs local question interaction and emits the first positive immediately. `safety_capture.py` checks an atomic age/pregnancy/question/answer scope and validates every value before appending worker facts and recomputing backend urgency. Browser elapsed time and pre-existing-answer counts are labelled device-reported rather than independently observed field results.

`browser_rules.js` mirrors the Python engine. The standalone offline HTML captures safety data locally and exports JSON for manual worker confirmation; import does not trust its urgency. It is not a complete offline Streamlit app or automatic sync. The FHIR R4 document-shaped export contains Patient, Encounter, Composition, observations/history answers, provenance, tasks and doctor care plan with internal references. Provincial implementation-guide and DHIS2 interoperability have not been validated.

The doctor can record or upload patient guidance and explicitly confirm that it matches the current written plan. Its encrypted file is linked to that response; the downloaded HTML card embeds the approved recording for offline playback. Missing or expired files retain their audit reference. English/Urdu interface and bounded speech routes, a partial fixed-audio bundle and manual regional recording/interpreter read-back are present. Full regional interfaces/automatic STT/TTS, native-speaker/phone validation, real clinician accounts, external delivery, verified facilities/stock and clinical approval remain external or deferred. The complete Streamlit workflow still requires its server; a downloaded HTML/audio card is independently readable offline. District analytics continue using the legacy ledger; exported consultation outcomes are not silently counted as district evidence.
